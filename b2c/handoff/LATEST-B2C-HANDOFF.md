# Latest B2C handoff addendum

## Latest patient-app changes — 11 October evening

- Program cards use the shared translucent folder design on home and refill. Refill cards use their own measured SVG clipping path rather than reusing home dimensions, and omit the extra front badge. Paper count is capped at four while complete consultation history is retained. Front cover remains still; paper movement respects reduced-motion preferences. History currently includes the selected consultation and labels each row “ปรึกษาวันที่ …” with the date beside the title; excluding the current record was proposed but not implemented.
- Treatment detail has a red, standard-size text action centered outside all record cards at the bottom of treatment detail: **พักโปรแกรมการรักษา**. It opens the shared confirmation sheet/modal. Confirmation persists only the selected program as paused, suppresses its future follow-up reminder/join eligibility and keeps clinical history readable. Cancelling makes no change. Paused folders are muted and explicitly labelled; they still open. Paused folders sort after active folders. “กลับมารักษาต่อ” proposes the earliest available appointment with the assigned doctor, offers another date/time, and only reactivates after appointment confirmation. Cancelling preserves pause. Completed consultation numbering is retained; reactivation does not invent a completed encounter.
- Pause persistence is prototype-only `localStorage["krane.paused-programs.v1"]`, keyed by category with `state`, `pausedAt`, and on confirmed resume `resumedAt`/`appointmentAt`. It is not account-scoped or an authoritative clinical case record. Production must use an authenticated case ID, cancel the next appointment atomically, notify the assigned clinician, audit the change and revalidate doctor-specific availability and lock the confirmed resume appointment. Prototype scheduling shares the deterministic appointment availability fixture, not a real doctor calendar. The current UI does not send a doctor notification or change prescriptions, medicine orders, billing or clinical instructions. Clearing browser storage clears this prototype state.
- CSAT requires all four ratings in this order: waiting time, combined video/audio, doctor, overall satisfaction. Dismissal keeps the review pending. Successful submission closes the sheet and opens **SID-050 / #feedbackdone**, whose CTA returns home. `#feedback` remains a route alias to the review sheet, not a standalone screen.
- Shared modal chrome: X close on both layouts, one drag handle on mobile only, scrim/Escape dismissal. Screen-directory previews stay in the right canvas and contain no preview-only explanatory labels; cloned controls remain noninteractive previews. Help choices now use outlined cards like other choice dialogs.
- Tracking and notifications use consistent status labels/icons. The delivery tag says **กำลังจัดส่ง**, and the location action has the same height. Notification descriptions are retained. Activity retains five order cards without embedded progress bars.
- Appointment rows are grouped by hour, but available slots pack left with no empty minute columns. Unavailable starts are omitted. Changing day clears selection; booking still requires an available slot.
- Receipt and certificate links use `assets/documents-v1/receipt-v3.pdf` and `medical-certificate-v3.pdf`, with the final blue Krane logo. They remain demonstration documents.
- Latest broad evidence: [night QA](QA-NIGHT-2026-10-11.md). Follow-up behavior evidence: [program pause and review completion](QA-PROGRAM-PAUSE-2026-10-11.md). Earlier CMS/brand reports retain their original scope; they were not rerun merely because this B2C change shipped.

Refill modal: “ยาทั้งหมดที่เติมได้” uses the shared secondary CTA, retaining the combined-order action. Removed its card subtitle and the refill-limit helper sentence from this modal.
