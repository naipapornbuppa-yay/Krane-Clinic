## Confirmed defect and fix

**P2 — blocking third-party font dependency; fixed.** Routes: B2C app, its embedded landing and associated public detail pages. Viewports: mobile 390 and desktop 1440, also covered by the six-width chrome suite.

Reproduce on the baseline: open `/b2c/krane-b2c.html?entry=partner` with the Google Fonts CSS request stalled/unavailable, or load the embedded landing under the same network condition. The token stylesheet uses a remote `@import`; the embedded landing additionally requests the provider directly. This adds a remote render/script-start dependency. Expected: core patient UI and fonts work from the application host. Actual: dependency requests are present, with intermittent DOM-ready/navigation timeouts observed during this run. Not every initial timeout can be attributed uniquely to this dependency; host/browser elapsed time also diverged.

Fix: vendor the same font families and weights with their OFL licenses; serve them through `b2c/fonts.css`; replace the remote token import and duplicated public-page font links; update token cache versions. Inter, previously requested by public pages, is preserved. No questionnaire, question order, treatment rule or app timer changed. Local font payload is approximately 3.3 MB across 19 TTF files; browsers request the faces they use. Visual comparison of mobile checkout and desktop partner identity showed the same intended typography/layout.

Retest: provider-blocked font regression passed; final contract 170/170; chrome 114/114; real-entry 3/3. [Mobile checkout](qa-night-2026-10-13/payment-390.png), [desktop identity](qa-night-2026-10-13/partner-patient-info-1440.png).

## Harness findings, separate from product defects

Initial concurrent runs recorded navigation/action timeouts. Matching sometimes still displayed a few elapsed seconds when the Node-side action timeout had expired. The same route changed correctly when directly observed. Isolated runs, foreground pages and configurable `QA_TIMEOUT_FACTOR=20` allowed completion. Browser launch now prevents background timer throttling; timed contract routes wait for the expected screen with a bound, instead of relying solely on a fixed sleep. No assertions or contract entries were removed. The insurance document switch passed on isolated retry, so it is recorded as intermittent rather than a confirmed unresolved product defect.

The pre-fix local contract run had 3 failures/170 checks; a live run had 2 failures/163 executed checks (preview loading and the old explicit 12-second partner wait). These are retained in evidence and are **not** reported as passes. The final post-fix local run is the 170/170 result above. No P0/P1 defect was confirmed by the completed frontend checks; this is not proof that all possible edge conditions are absent.
